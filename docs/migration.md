# 開発環境の作り直し

作り直せる開発環境では、古い環境とテストデータを削除し、最新版のコードと設定で再構築してください。セーブやビルド済み成果物の移行は不要です。

1. シナリオの原本、元画像・フォント、必要な設定と資格情報を残します。
2. 旧環境へのWebhookや配信を止め、対象の開発環境と不要なテストデータを削除します。
3. 最新の`settings.yaml.template`を`settings.yaml`へコピーし、必要な設定を入れます。`.env.template`と[READMEの導入手順](../README.md#インストール手順)に従って環境を作成します。
4. 管理画面の認証とシナリオの入力元を設定し、シナリオを再ビルドします。Google Sheetsを使う場合は、新環境のサービスアカウントへ共有します。
5. WebhookやページのURLを新環境へ合わせ、会話・ページ連携・使用する非同期処理を確認します。Webchatのテスト用セーブは「最初から」でリセットします。

AWSでは、スタック削除後も`Retain`指定のS3バケット・DynamoDBテーブル・DLQなどが残ります。不要な残存資源と古いECRイメージも片付けてください。DynamoDBの削除保護が有効なら、対象を確認して解除します。共有資源やシナリオの原本は削除対象に含めません。

古い台本を再利用する場合は、次だけ確認してください。

- `options.scenario_version`を台本の版に合わせ、More等の使用するpluginを有効にします。設定テンプレートの既定はversion 3です。
- `@forward`の第3引数と、`@delay 秒 Bot名 action`の第4引数はinterface指定です。この位置にメモを書いていた場合はコメント行へ移します。

機能ごとの設定は、[シナリオ作成](scenario-authoring.md)、[Webchat](webchat.md)、[LIFF連携](liff-webchat-api.md)、[リッチメニュー](richmenu.md)を参照してください。
